# CampusCloud Deployment Guide

This guide details the deployment architecture and configuration for **CampusCloud** across production environments and optional alternative cloud targets.

---

## 1. Actual Production Deployment Architecture

CampusCloud is deployed in production using a decoupled full-stack cloud setup:

- **Frontend:** Hosted and served via **Vercel**
- **Backend:** Hosted and executed via **Render** (Node.js Web Service)
- **Local / Preview / Offline Mode:** Standalone Express server (`backend/local-dev/server.js`) with built-in JSON file database and file-system storage emulation, or optional AWS cloud backing.

```
┌───────────────────────────────┐         HTTPS / REST API         ┌──────────────────────────────┐
│        Vercel (Edge)          │ ───────────────────────────────> │         Render (PaaS)        │
│                               │                                  │                              │
│  - React 18 + Vite SPA        │ <─────────────────────────────── │  - Node.js 20 Express Engine │
│  - TailwindCSS Design System  │           JSON Responses         │  - Local-dev / AWS Handlers  │
│  - Client Routing & UI State  │                                  │  - JSON / DynamoDB Stores    │
│  - Axios HTTP Interceptors    │                                  │  - Uploads / S3 Ingestion    │
└───────────────────────────────┘                                  └──────────────────────────────┘
```

## 2. Frontend Deployment: Vercel

The frontend is a React 18 Single Page Application created with Vite and styled with TailwindCSS.

### Configuration (`vercel.json`)
At the project root and in `frontend/`, `vercel.json` configures the build and single-page application route rewrites:
```json
{
  "framework": "vite",
  "buildCommand": "cd frontend && npm install && npm run build",
  "outputDirectory": "frontend/dist",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

### Required Environment Variables on Vercel
Set these in the **Vercel Project Dashboard** under **Settings → Environment Variables**:

| Variable | Description | Example / Default |
|---|---|---|
| `VITE_API_URL` | Base URL of the backend API on Render (or API Gateway) | `https://campuscloud.onrender.com` |
| `VITE_APP_NAME` | Display name of the application | `CampusCloud` |
| `VITE_ENVIRONMENT` | Target environment label | `production` |

> **Note on `VITE_API_URL`:** The frontend Axios client in `frontend/src/lib/api.js` automatically normalizes this value and appends `/api` if not already present.

### Deployment Steps (Vercel)
1. Link your GitHub repository (`https://github.com/24archit/CampusCloud`) to Vercel.
2. Select the framework preset: **Vite**.
3. Set the Root Directory to repository root (`.`) or `frontend/`.
4. Configure Build Command: `npm run build:frontend` (or default from `vercel.json`).
5. Configure Output Directory: `frontend/dist`.
6. Add the environment variables above and trigger **Deploy**.

## 3. Backend Deployment: Render

The backend application runs on **Render** as a Node.js Web Service defined by `render.yaml`.

### Configuration (`render.yaml`)
```yaml
services:
  - type: web
    name: campuscloud
    runtime: node
    plan: free
    region: singapore
    buildCommand: npm run build
    startCommand: npm start
    envVars:
      - key: NODE_ENV
        value: production
      - key: LOCAL_DEV
        value: "true"
      - key: JWT_SECRET
        generateValue: true
```

### Backend Execution Model on Render
- **Build Command:** `npm run build` installs root dependencies, compiles the frontend into `frontend/dist`, and installs backend dependencies.
- **Start Command:** `npm start` executes `node backend/local-dev/server.js`, binding to `0.0.0.0` on the port assigned by Render (`process.env.PORT`).
- **Health Check Endpoint:** `GET /api/health` returns `{"status":"ok","timestamp":"..."}`.
- **Static Asset Serving:** When built as a monorepo, `server.js` automatically serves `frontend/dist` as fallback for non-API routes, allowing single-app hosting if needed.

### Backend Environment Variables on Render

| Variable | Required | Default / Recommended | Purpose |
|---|---|---|---|
| `NODE_ENV` | Yes | `production` | Runtime mode indicator |
| `PORT` | Auto | Render assigns automatically (e.g. `10000`) | Network listening port |
| `LOCAL_DEV` | Yes (for standalone) | `true` | Enables built-in JSON persistence & local storage |
| `JWT_SECRET` | Yes | Auto-generated by Render | Secret key for signing/verifying JWT tokens |
| `FRONTEND_URL` | Optional | `https://campuscloud.vercel.app` | Allowed CORS origin & base for shareable links |

## 4. Local Development Deployment

To run both services simultaneously on a local machine:

1. **Clone repository:**
   ```bash
   git clone https://github.com/24archit/CampusCloud.git
   cd CampusCloud
   ```

2. **Install all dependencies:**
   ```bash
   npm run install:all
   ```

3. **Start local development servers:**
   ```bash
   npm run dev
   ```
   - Frontend starts on: `http://localhost:5173`
   - Backend starts on: `http://localhost:3001`
   - Health check: `http://localhost:3001/api/health`

## 5. Alternative Cloud Target: AWS Serverless (Optional)

In addition to the primary Vercel + Render production deployment, the codebase includes Infrastructure as Code (`infrastructure/template.yaml`) and scripts for deploying to an AWS Serverless stack:

- **Compute:** AWS Lambda functions with API Gateway REST routes
- **Database:** Amazon DynamoDB (`campus-cloud-users`, `campus-cloud-resources`, `campus-cloud-shared-links`)
- **Storage:** Amazon S3 with presigned upload/download URLs
- **Auth:** Amazon Cognito User Pool or custom JWT verification

### AWS SAM Deployment Steps (Optional)
```bash
cd infrastructure
sam build
sam deploy --guided
```

## 6. Deployment Troubleshooting

| Issue | Cause | Solution |
|---|---|---|
| **CORS Errors in Browser** | Mismatched frontend origin | Verify `FRONTEND_URL` on Render matches your Vercel URL. The backend CORS middleware permits credentials and custom headers. |
| **API 404 Route Not Found** | Missing `/api` prefix | Frontend API client automatically prepends `/api`. Ensure all endpoints match `/api/*`. |
| **Render Cold Start Delay** | Render Free Tier spins down after 15 minutes of inactivity | Allow 30-50 seconds for first request wakeup, or ping `GET /api/health`. |
| **File Upload Size Error** | Request payload exceeds limits | In standalone mode, file uploads are limited to 50MB. In AWS mode, S3 presigned URLs bypass compute limits. |
